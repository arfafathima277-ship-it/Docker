# Docker Volumes

## What are Docker Volumes?

Docker Volumes are used to store and manage data generated by Docker containers. They allow data to persist even if a container is stopped, removed, or recreated.

Without volumes, all data inside a container is lost when the container is deleted.

---

# Why Do We Need Docker Volumes?

By default, container data is temporary (ephemeral).

Docker Volumes provide:

- Persistent data storage
- Data sharing between containers
- Easy backup and restore
- Better performance
- Independent storage from containers

---

# How Docker Volumes Work

```text
          Docker Host
      ┌───────────────────┐
      │                   │
      │  Docker Volume    │
      │       │           │
      └───────┼───────────┘
              │
     ┌────────┴────────┐
     │                 │
┌──────────┐     ┌──────────┐
│Container1│     │Container2│
└──────────┘     └──────────┘
```

Both containers can access the same volume.

---

# Types of Docker Storage

## 1. Volumes

- Managed by Docker
- Recommended for persistent data
- Stored outside the container

---

## 2. Bind Mounts

- Maps a host directory to a container.
- Useful during development.

Example:

```
Host Folder
      │
      ▼
Container Folder
```

---

## 3. tmpfs Mount

- Stores data in RAM.
- Data is deleted when the container stops.
- Used for temporary or sensitive data.

# Docker Volume Commands

## Create a Volume

```bash
docker volume create myvolume
```

---

## List Volumes

```bash
docker volume ls
```

---

## Inspect a Volume

```bash
docker volume inspect myvolume
```

---

## Remove a Volume

```bash
docker volume rm myvolume
```

---

## Remove Unused Volumes

```bash
docker volume prune
```

---

# Mount a Volume to a Container

```bash
docker run -d \
--name nginx-container \
-v myvolume:/usr/share/nginx/html \
nginx
```

Here,

- **myvolume** → Docker Volume
- **/usr/share/nginx/html** → Container directory

# Volume Lifecycle

```text
Create Volume
      │
      ▼
Attach to Container
      │
      ▼
Store Data
      │
      ▼
Container Deleted
      │
      ▼
Volume Still Exists
```

---

# Advantages

- Persistent storage
- Data survives container deletion
- Easy sharing between containers
- Faster than writing inside the container
- Easy backup and migration

---

# Real-Time Example

A MySQL database runs inside a Docker container.

Without a volume:
- Deleting the container also deletes the database.

With a volume:
- Database files remain safe even after the container is removed.
- A new container can reuse the same data.

# Hands-on

### Create a Volume

```bash
docker volume create mydata
```

### Verify

```bash
docker volume ls
```

### Run a Container

```bash
docker run -it --name ubuntu-container -v mydata:/data ubuntu
```

### Create a File

```bash
echo "Hello Docker" > /data/file.txt
```

Exit the container.

### Remove the Container

```bash
docker rm -f ubuntu-container
```

### Create Another Container

```bash
docker run -it --name ubuntu2 -v mydata:/data ubuntu
```

### Verify the File

```bash
cat /data/file.txt
```

Output:

```
Hello Docker
```

The data still exists because it is stored in the Docker Volume.

# Interview Questions

### 1. What is a Docker Volume?

A Docker Volume is a persistent storage mechanism that stores container data outside the container.

---

### 2. Why are Docker Volumes used?

To preserve data even after a container is deleted.

---

### 3. Where are Docker Volumes stored?

On the Docker host under Docker-managed storage.

---

### 4. Can multiple containers share the same volume?

Yes. Multiple containers can mount and use the same Docker Volume.

---

### 5. What is the difference between a Volume and a Bind Mount?

| Volume | Bind Mount |
|---------|------------|
| Managed by Docker | Managed by the host OS |
| Better for production | Better for development |
| Portable | Depends on host directory |

---

### 6. Which command creates a Docker Volume?

```bash
docker volume create <volume-name>
```

---

### 7. Does deleting a container delete the volume?

No. Docker Volumes remain unless they are deleted manually.

---

# Summary

- Docker Volumes provide persistent storage.
- Data survives container removal.
- Volumes can be shared across containers.
- Ideal for databases and stateful applications.
- Managed directly by Docker.
